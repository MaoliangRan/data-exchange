# 市场调研

对某个行业或产品执行端到端市场调研，产出一份**每个关键数据都有来源链接**的市场调研报告。

## 核心原则（不可妥协）

1. **所有数字必须有出处**。报告中的每个市场规模、份额、增长率、出货量数字，都要有对应来源和可访问链接。找不到可靠来源就写"未找到可靠公开数据"，绝不编造或"凭印象估算"。
2. **区分事实与推断**。引用的数据标来源编号；自己的分析判断必须明确标注"（分析）"，不能写成确定事实。
3. **注明口径**。引用数据必须带上统计口径：数据年份、地域范围（全球/中国/北美）、统计方式（按营收/出货量/销量）。"市场份额 30%" 这种没有口径的数字没有意义。
4. **置信度内联标注**。市场规模、份额、增速等关键数字若没有 ≥2 个独立来源相互印证，正文在数字旁标注"（低置信）"；来源发布超过 3 年的标注"（历史数据）"。

## 第一步：明确调研范围

开始检索前确认以下信息，不确定就问一句，不要猜：

| 维度 | 说明 | 默认值 |
|---|---|---|
| 调研对象 | 整个行业还是某个具体产品？ | 必须确认，模糊就问 |
| 地域范围 | 全球 / 中国 / 北美 / 欧洲… | 全球，同时补充中国数据 |
| 时间范围 | 最新数据还是历史演变？ | 近 12-24 个月的最新数据 |
| 输出格式 | Markdown+Word / PDF / PPT | Markdown + Word |

"安防行业"和"家用智能摄像头"是两个完全不同的调研；"新能源行业"的规模和"动力电池"的规模差一个数量级。调研对象模糊时先澄清再动手，避免整份报告跑偏。

确认范围时用了默认值或做了主观取舍（如"默认包含轮式机型"），要记录为关键假设，写入报告头部"关键假设"行——读者需要知道调研边界是怎么定的。

### 调研计划前置（可选，默认关闭）

确认范围时一并问一句：**是否需要"调研计划前置(检索前先展示调研计划——3-7 个关键问题拆解 + 来源策略)"**。只在用户明确需要时执行，否则直接进入第二步：

- **需要**：检索前先展示调研计划——3-7 个关键问题拆解 + 来源策略。关键问题是报告要回答的核心疑点（如"市场规模各机构口径差异多大？""份额第一是谁、按什么口径？""技术路线之争到什么程度了？"），每个问题应对应报告的一个章节；来源策略写明优先信源类型和中英文检索词方向。展示后直接开始检索，不等二次确认；用户中途对计划有调整意见时，按调整后的计划执行。
- **不需要**：跳过本节，直接检索。

问这一句的成本很低，但能让用户在重度检索前看到调研会回答什么、不回答什么，避免整份报告跑偏后返工。

## 第二步：检索信息

先读 `references/source-guide.md`（信源分级与检索技巧），然后按以下顺序多轮检索：

1. **市场规模与增长**：`<行业> market size 2025 CAGR`、`<行业> 市场规模 2025`。中英文各搜一轮——很多行业只有海外研究机构覆盖，只搜中文会漏掉主要数据。
2. **主要玩家与份额**：`<行业> market share 2025`、`<公司名> annual report / 财报 / 10-K`。份额数据至少找 2 个独立来源交叉验证。
3. **市场趋势**：并购动态、新进入者与退出者、价格走势、政策变化、需求端变化。
4. **技术趋势**：新技术路线、头部公司的技术布局公告、专利与标准动态。
5. **补充验证**：对将写入报告的每个关键数字，回到来源页面核对数字和口径没有被误读；检查链接是否可公开访问。

相互独立的检索可以并行发起，加快速度。

## 第三步：撰写报告

按 `references/report-template.md` 的结构撰写，保存为 `市场调研报告-<主题>-<YYYYMMDD>.md`（当前工作目录）。

引用格式（可点击跳转）：正文数据后写成 `[n](#ref-n)`，报告末尾"参考来源"每条编号后加锚点 `<a id="ref-n"></a>`——md 里点击编号跳到对应条目；转成 Word 后编号变为内部超链接、条目变为书签。示例：

```markdown
2025 年全球出货超 1.8 万台 [1](#ref-1)。

## 8. 参考来源

1. <a id="ref-1"></a>IDC, "Humanoid Robotics Commercialization Trends 2026", 2026-04-23, https://... （研究机构）
```

表格中的来源列同样用 `[n](#ref-n)`。参考来源按编号列出——机构/媒体、标题、发布日期、完整链接、信源层级。

禁止事项：

- 不得出现没有来源编号的关键数字
- 不得把预测、传闻、"分析认为"写成确定事实
- 来源链接必须是检索时实际访问确认过的 URL，不得凭印象拼 URL
- 付费报告的数字只能链接到可公开访问的页面（新闻稿或转载页），并注明原始出处

**交付前自查（全部通过才交付）**

- [ ] 正文每个 [n] 都能在"参考来源"找到对应条目；反向核对：每条来源都被正文引用 ≥1 次，没有被引用的条目直接删除
- [ ] 关键数字都有来源编号 + 口径 + 置信度标注（低置信/历史数据）
- [ ] 来源链接都实际访问过，且可公开访问
- [ ] 来源冲突已并列呈现，没有静默取舍
- [ ] 分析性内容标注了"（分析）"，关键假设写入了报告头部

## 第四步：生成 Word 并交付

Markdown 报告完成后，运行本 skill 自带的转换脚本生成同名 Word（`市场调研报告-<主题>-<YYYYMMDD>.docx`）：

```bash
python "<skill 目录>/scripts/md_to_docx.py" 市场调研报告-<主题>-<YYYYMMDD>.md
```

- 脚本依赖 python-docx，首次使用先 `python -m pip install python-docx`
- 转换会把正文 `[n](#ref-n)` 转成 Word 内部超链接、"参考来源"条目转成书签（ref-n → 书签 ref_n），裸 URL 转外部链接
- 转换后用 docx skill 的 postcheck.py 校验并修复所有 ❌ 错误；docx skill 不可用时，至少核对书签/链接数量与参考来源条目数一致

报告完成后在对话中给出：

1. 3-5 句执行摘要，含最关键的 2-3 个数字及其来源
2. 报告文件的 Markdown 和 Word 链接
3. 数据可信度说明：哪些数据来自 Tier 1/2 信源、哪些只有单一来源、哪些数字存在来源冲突（冲突数字在报告中也要并列呈现，不能静默选一个）

用户需要 Word 或 PPT 版本时，再调用对应的 docx / pptx skill 转换，转换后注意核对引用编号和链接未被破坏。
